## 书评之间的关联

这 5 篇书评不是随机选择的，它们之间有清晰的主题关联——**共产主义/极权主义的多个面向**：

- **斯考森《赤裸裸的共产党》**：冷战美国保守派的"反共圣经"，从外部看共产主义阴谋
- **阿伦特《极权主义的起源》**：政治哲学的深度分析，从结构内部解剖极权主义
- **冯哲芸《唯红花绽放》**：当代记者的纪实报道，从个体经验看习近平时代的身份压缩
- **伯林《苏联的心灵》**：观念史学家的内部观察，从知识分子视角看苏联文化
- **斯诺《红星照耀中国》**：左翼记者的理想化记录，从革命初期看运动的"理想面"

每篇书评都推荐了其他几篇作为对照阅读，形成了一个完整的阅读矩阵：
- 阿伦特 vs 斯考森：深度分析 vs 浅层反共
- 斯诺 vs 阿伦特：理想面 vs 恐怖面
- 伯林 vs 阿伦特：微观个体 vs 宏观结构
- 冯哲芸 vs 伯林：当代中国 vs 苏联历史

## 工作流程

每篇书评的流程：
1. 搜索书籍资料（web_search + web_fetch）
2. 子代理（sessions_spawn）撰写 Markdown 书评
3. pandoc 生成 HTML
4. weasyprint 生成 PDF
5. 复制到 book-reviews/书评/2026-07-27/ 目录
6. git push 或 GitHub API 上传到 GitHub

## 网络问题

今晚网络状况极差，git push 大文件（PDF 600-770KB）反复超时（HTTP 408 / TLS handshake timeout）。最终策略：
- MD + HTML 通过 git push 推送（文件小，一般能成功）
- PDF 通过 GitHub API（gh api --method PUT）单独上传
- 发现 GitHub 默认分支是 `main`，API 上传到了 `main`，而 git push 推的是 `master`
- 最终通过 git merge origin/main 合并两个分支

整个过程反复重试了几十次，从 21:42 持续到 00:20 才全部上传成功。daliao 很有耐心，不断说"继续推送"。

## 技术备忘

- pandoc + weasyprint 的书评生成流程稳定可靠
- GitHub API 上传大文件需要用 python3 生成 JSON payload（base64 编码），不能用命令行参数（Argument list too long）
- GitHub 的 `main` 和 `master` 分支问题需要注意——gh api 默认推到 `main`，git push 推到 `master`
- 网络差时，分开推送小文件比一起推大文件成功率高
